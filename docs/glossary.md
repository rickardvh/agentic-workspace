# Public Glossary

Use this small vocabulary for stable public concepts. Module-specific terms belong in their domain docs.

| Term | Meaning |
| --- | --- |
| Operating context | Source-owned durable or current context whose availability can materially change agent behavior. It excludes general repository ingestion, indexing, embeddings, RAG, knowledge graphs, and ordinary source/docs/tests retained by their canonical owners. |
| Current operating contract / decision | The smallest admitted, task-shaped control projection for what matters now, what action is supported, and what claim/continuation boundary applies. |
| Progressive disclosure | Keeping irrelevant context and capabilities absent while making deeper detail reachable through exact selectors, skills, operations, or owners. |
| Resolve / act / reconcile | Resolve the current contract, perform one bounded supported action, then admit the result and determine claims, residue, continuation, or terminal state. |
| Module | A peer extension that declares bounded resources, procedures/skills, typed operations, ownership, relevance, and result semantics without changing the generic loop. |
| Repo customization / control input | Host-owned config, obligations, skills, guidance, ownership, or operations that materially constrain the current contract. It is not a generic personality framework. |
| External adapter | A consumer/transport of stable AW operations into another host. It owns vendor integration and does not become core/module authority. |
| Owner / authority | The source allowed to define or mutate a concern. Observation, transport, generation, or display does not grant ownership. |
| Claim boundary | The strongest conclusion justified by admitted intent and evidence. Passing a command cannot silently widen it. |
| Necessary surface | The smallest supported checked-in routing/control footprint for a host repository. Exact files are contract-generated. |
| Support-bearing release | A versioned release whose promotion and install receipts bind source, artifacts, hashes, compatibility, and the public install command. |

Planning, Memory, and Verification are current first-party module examples. A reader does not need their domain vocabulary to understand core AW.
