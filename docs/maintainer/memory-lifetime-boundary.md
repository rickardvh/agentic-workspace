# Memory lifetime boundary

Memory selection disposition and terminal disposition have different effects.
`memory.dispose` continues to preserve source text. Its `retire` or `promote`
label only suppresses selection. `memory.retire-terminal` removes one exact
source and its manifest declaration after explicit terminal-intent and future-value
judgment. It never treats age, a stale dependency, or the selection label as
permission to delete.

Ordinary Memory detail exposes the current terminal request and protected
consumers. Retired/promoted notes and changed advisory dependencies nominate a
value question. The quiet request also supports readonly nomination of another
exact declared source: keep all judgment booleans false to obtain a fresh binding.
An agent must read the source and any prior human retention requirement before
asserting terminal intent, no unresolved intent and no continuing value. A prior
promise to preserve source text is not overridden by selection retirement.

Removal binds the source, complete manifest preimage/postimage, sibling sources
and current consumers in Planning, Memory, Verification, proof, instructions,
system intent, reconstruction, evaluations and local decision-point admissions.
References from durable facts or other notes protect the source. Linked sources,
unreadable boundaries and changed consumers preserve material. Manifest comments,
line endings and unrelated declarations survive. The Memory effect lock and
custody-bound local recovery record cover interruption before publication, between
manifest replacement and deletion, and before/after commit. No tracked tombstone,
per-retirement ledger or history mirror is created. Local attempt records remain
outside the checked-in retention claim.
