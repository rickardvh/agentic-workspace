# First-party activation ownership

The current ingress is disposable material or unmet need, followed by native
owner composition and optional source-owned procedure occasions. This inventory
records the migration boundary; procedure resources own the actual declarations.

| Surface | Current disposition and receiving outcome |
| --- | --- |
| Setup / Configuration | `workspace-setup-jumpstart` handles observations and binding Configuration consequences; current setup choices and usable configuration remain owner-managed. |
| Intent / scoped instructions | `workspace-intent-discovery` and `workspace-instruction-correction` handle clarified outcomes, facts and conflicts; the actual intent/instruction source owns any durable change. |
| Planning | `planning-work` handles continuity needs and binding Planning consequences; closeout/review methods handle their narrower needs. Direct work creates no plan. |
| Memory / decisions | Correction selects the strongest destination; `memory-capture` serves current binding future-value questions. Memory hygiene serves explicit residue needs. Legacy consultation/router/refresh/upgrade helpers remain direct selected methods, not separate activation authorities. |
| Verification / review | `workspace-proof-selection` handles unmet prerequisites before execution and binding proof consequences. Repository `pr-review-recheck` remains available only to an eligible, externally initiated reviewer. |
| Assignment / Delegation | `planning-assignment` and repository `delegation-handoff` expose existing binding continuation. Native Assignment still admits local work or exact non-local dispatch/handoff. Reading or omitting either method cannot waive it. |
| Resources | `workspace-resources` serves actual acquisition, recovery and cleanup needs; the resource owner performs effects. |
| Skills / reusable method | Existing procedure resources contain occasions, applicability and outcome. Migrated registry hint taxonomies are removed. Unmigrated specialised maintainer methods remain ordinary direct skill use; this lane does not author learned skills. |
| Independent modules / external material | The same bounded observation/need shape carries arbitrary producer identities. Repository-authored procedure declarations participate without a core identity branch. Current external state remains unverified until its responsible owner observes it. |
| Ordinary repository owners | Code, tests, configuration and documentation are direct receiving sources. Current consequence evidence, rather than copied lesson text, supports stronger-owner disposition. |

`workspace-startup` remains the small entry and lifetime recognition rule. Planning
bootstrap/reporting and Memory consultation/router/refresh/upgrade helpers need no
additional activation registry: their current capable owner or selected procedure
already supplies the relevant direct entry. Native owner restrictions remain
visible even when every optional skill is absent.

Deterministic proof establishes carriage, authority, currentness and composition.
Ordinary-agent outcomes require the shared installed-consumer harness. Neither
this inventory nor a successful skill read establishes real-agent acceptance.

The shared consumer harness exposes four on-demand families: `activation-material`,
`activation-no-retention`, `activation-assignment` and `activation-local`. They do
not expand scheduled recurrence. Material proof uses a separately owned Docker
PostgreSQL fixture, a non-secret configuration consumed by the actual check,
fresh agent processes and a stopped-service negative. The actor receives ordinary
tasks and repository files, without injected AW routes or owner packets.

For unreleased changes, `stage_native_npm.py --consumer-candidate` freezes a clean
source commit and one paired native target archive. The shared installer verifies
its digest and native provenance, and accepts it only for the standalone profile.
This bounded candidate cannot satisfy the complete published release inventory.
First failures and subsequent observations remain separate result files.
