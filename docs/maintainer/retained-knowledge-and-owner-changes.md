Priority 2 under #3208 composes existing owners through the main workspace skill
and ordinary Rust-backed requests. Semantic nomination remains agent/human
judgement. Currentness, destination restrictions, exact publication and recovery
remain executable owner responsibilities.

## Knowledge destinations

| Material | Current destination and consequence |
| --- | --- |
| Useful advisory observation | `memory.advisory_capture` publishes one bounded lesson, future-value rationale and exact dependency revisions into the existing Memory manifest/note tree. |
| Settled material decision | `decision_sources.capture` targets an admitted repository convention directly; otherwise `memory.capture` supplies fallback custody. |
| Existing advisory lesson | Memory retain/retire/promote disposition preserves the source; promotion requires independently admitted whole-lesson absorption. |
| Task-only correction or insufficient future value | No retention; no new archive record or task lifecycle. |

Advisory capture works even when a stronger repository decision archive exists.
Its `lesson` and `rationale` are not a decision record, policy, proof or target
evidence. `confirm-retention` admits the exact proposal, separately from material
authorship, which remains unattributed. Existing exact Memory policy delegation
can admit the retention choice without another human answer. A no-retention
advisory request returns without publication or an authorisation roundtrip.

The note and manifest use the existing bounded capture publication/recovery
implementation. The advisory representation has its own request/result identity
and does not enter decision-continuity admission. Relevant notes remain advisory;
an exact changed or missing dependency suppresses selection with a reconciliation
diagnostic. Unrelated notes remain absent. Publication does not prove the lesson
true forever. Future corrections use the existing disposition owner.

The pre-existing repository/fallback decision implementation covers human answers,
explicit exact-scope agent grants, authorship separation, no-retention,
supersession, stronger-owner preference and progressive rationale. This tranche
does not add another decision archive or reinterpret former Memory as decisions.

## Corrections, friction and initiative

The existing correction skill selects lifetime and owner from meaning. Machine
behaviour stays in local ignored instructions; portable repository behaviour stays
in checked-in instructions. Decisions, advisory knowledge, owner defects and
proportionate Planning retain their own destinations. An absent host-delivered
correction cannot be inferred from hidden conversation or promised as retained.

Instruction and configuration edit requests accept optional `nomination` context.
It identifies trusted correction, material owner friction or a repository
opportunity, and carries bounded current evidence, reason, expected effect,
validation and supersession meaning. The proposed delta remains the destination
owner's ordinary `content` or `key/value`; there is no parallel change format.
Evidence references are confined exact source paths and must match current bytes.
The nomination is bound to the proposal and invocation, so stale evidence cannot
authorise a write.

The ordinary configuration contract lists supported source/key pairs; full value
schemas are delivered through `configuration/read-choice/v1` for the selected
pair. Every edit still validates its value against that source-owned schema
before disposition or publication. Advisory and nomination discovery therefore
fit within the existing ordinary projection bound without copying every choice
schema into unrelated work.

Current `workspace.improvement_latitude` controls opportunity proposals. `none`
and `reporting` produce reports; `conservative` allows proposals within
current work; `proactive` also permits proactive proposals. None grants mutation.
The destination's exact current delegation or bounded human answer is still
required. Package defects report to the package owner rather than borrowing
host-repository initiative latitude. The existing configuration writer can edit
the latitude under its normal explicit authority.

Method adaptation cannot alter existing instruction `paths`, `protect`, `checks`
or `reconcile` floors, and nominated configuration method changes are limited to
the existing invocation choice. Broader policy changes require an explicit
owner correction under the ordinary authority boundary. Nomination never waives
other instructions, safety ceilings, proof, review or publication protection.

`already-owned` requires equality with the receiving owner's actual current
semantic postimage; instructions additionally require current publication
admission. A related filename does not suffice. Repeating a completed change
becomes quiet through this comparison. `report` and `no-action` have no durable
backlog, suppression list or continuation store. A changed source needs a fresh
judgement. Other code, skill and Verification repairs remain work under their own
existing procedures; these two typed writers do not claim universal mutation.
