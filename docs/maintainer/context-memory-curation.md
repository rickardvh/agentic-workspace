# Context and Memory curation evidence

This change reduces the checked-in Memory routing manifest from 10 notes to 6. It removes 19 historical, example, duplicated-ledger, or procedural files; merges the still-current recurring failure into the canonical mistakes note; and retains only the routing index plus current runtime, Memory, Planning, consolidation, and recurring-failure context.

| Disposition | Count | Reason |
| --- | ---: | --- |
| Retained manifest routes | 6 | Current architecture, ownership, routing, or recurring-failure evidence |
| Removed files | 19 | Example content, superseded history, duplicate ledgers, or active procedure owned elsewhere |
| Consolidated findings | 1 | The recurring Planning-residue failure remains in the canonical mistakes note |

The route budget is measured by executable fixtures:

- an unmatched direct task returns zero notes and `decision=no-memory-required`;
- representative runtime, Memory, and Planning paths select their canonical note plus the routing index;
- unrelated paths do not select optional Memory;
- stale or renamed canonical sources fail admission instead of silently falling back;
- the manifest stays at or below six durable notes until new evidence justifies expansion.

Proof procedures and active work state are intentionally excluded from Memory. Verification owns proof strategy, Planning owns active continuation, and runtime/contract registries own generated/source and context-authority boundaries.
