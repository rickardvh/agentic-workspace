# Native workflow artifact profile

The existing `repo-owned` profile uses current bounded Planning sources and
worktree-local selection. Its projection points at the actual current Planning
owner, preserving pending decisions, source gaps and mutation custody. It does
not recreate historical aggregate queues, decompositions or record forests.
Selecting the profile cannot establish that a Planning reconciliation completed.
The method projection carries only current owner and subject references; detailed
Planning state remains with the existing Planning projection.

The existing `gemini` profile permits optional runtime scratchpads. Absence of
`implementation_plan.md`, `task.md` and `walkthrough.md` requires no transfer or
new artifact. Existing or unreadable files are retained as exact source
observations, without interpreting their names or contents as current work
custody. Their unresolved durable-fact transfer restricts existing delegation
and completion/review boundaries, not unrelated task execution. The typed native
scratchpad-to-current-Planning update remains unavailable; this projection does
not claim to perform that transfer.

Configuration and relevant scratchpad revisions participate in existing
capability currentness. Changes invalidate previously returned requests and
actions without changing material Planning work identity. Source observations
are compact and preserve bytes; neither profile grants proof or acceptance.
