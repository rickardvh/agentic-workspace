# Execution continuity at the action frontier

A current binding nonlocal Assignment with a sealed handoff and a supported
selected process transport now exposes `delegation.dispatch` directly. The core
carries the same exact request and prerequisites previously returned in nested
detail. Explicit clients retain that request API. Local assignments stay direct;
manual and unsupported transports remain handoffs. Target comparison, override,
input completeness, capability and return judgement remain explicit decisions.

Planning similarly carries exact handoff retention and admitted/integrated return
adoption to its existing `planning.update` action. Current owner selection and
continuation custody are prerequisites, not inferred from the handoff. Unknown
observations and other-assignment continuity remain unresolved. Already retained
continuity and an already consumed identical result do not manufacture writes.
Continuation classification still selects frontier versus accepted_progress.

An exact pending Planning postimage exposes `planning.update-recover` only after
same-owner continuation is admitted. It cannot answer that semantic question,
authorise a selector transfer or introduce material. Original pending custody
remains visible. Recovery revalidates the exact postimage and current authority.

## Cost and authority

Each selected mechanical transition removes one model request-copying roundtrip:
ready dispatch, handoff retention, return adoption and admitted update recovery.
These are query-to-action transitions; there is no action execution loop. Effects
occur only through an explicit exact invocation. Worker output remains unproven;
Assignment admission, patch integration and Verification retain their own gates.

The frontier checks only the existing carrier for the exact dispatch identity.
In-flight/uncertain custody blocks launch. Exact terminal or committed replay goes
to the existing execution recovery path, which never starts a second worker. No
run-directory scan, queue, session, transcript or new durable cursor is added.

Existing read-only and patch lifecycle journeys now consume direct actions and
compare them to explicit requests. Existing interruption/replay, source drift,
foreign postimage, returned-result and no-op tests retain their authority classes.
The test delta adds assertions to those owners rather than a new adapter matrix
or CI job. Full Rust tests establish shared compilation/effect invariants; focused
public lifecycle and Planning tests establish the changed composition. This does
not prove provider economics, independence, all-release acceptance or task
completion from a successful worker process.
