Date: 2026-08-14

Issues reviewed: #2194, #2207, #2216, #2217, #2221, #2222, #2223, #2224, and #2266.

## Decision

The remaining integration intent is satisfied for the supported public operation boundary and configured local runtime. Merged children already provide generated Python and TypeScript consumers, installed-artifact conformance, assignment and delegation lifecycle enforcement, correction admission/promotion/lifecycle, and owner-bound evaluations. This change closes the missing correction operating loop: typed capture decisions, selective routing, authority-ranked compliance observations, contextual consequences and recovery, plus a second real longitudinal evaluation domain.

Live provider evidence remains intentionally narrower than deterministic portability proof. Existing Codex live runs are retained. A distinct vendor and a separately configured strong-tier comparative route were unavailable in this session and are recorded explicitly in `tools/model-cli-harness/external-agent-evaluation/provider-availability-2026-08-14.json`; no local fallback is represented as cross-vendor proof.

## Cost and authority boundary

No checked-in per-agent correction history or observation log is introduced. No-guidance work returns an empty route with zero artifact overhead. Guidance is subordinate to current user instruction and checked-in repo authority. Model prose, self-report, worker claims, Memory, and live-provider absence do not become proof or enforcement authority.

## Residue

Future credentialed provider runs may append live mixed-vendor evidence. They are longitudinal evidence, not an implementation blocker, because deterministic public-operation and failure-path proof is maintained and unavailable routes fail closed. Any future failure must create or reopen a narrow issue rather than weakening these boundaries.
