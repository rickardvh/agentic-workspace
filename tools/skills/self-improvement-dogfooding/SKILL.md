# Self-improvement dogfooding

This is repository-maintainer guidance, not package authority or an installed
product mode. Start with the repository's required `agentic-workspace start`
command and execute an actionable `primary_action` unchanged. Use the returned
`next_decision`; do not reconstruct deleted report, reconcile, proof, or skill
commands.

For one finding:

1. State the observed friction and evidence separately from diagnosis.
2. Classify it as repo-local, package-generic, or agent-runtime-specific.
3. Route it to the smallest current owner: direct code/test/check, scoped
   `AGENTS.md` rule, Memory advisory, Planning continuation, Verification policy,
   GitHub issue, PR/review comment, or explicit dismissal.
4. Prefer a stronger deterministic owner over permanent warning prose when the
   same mechanical failure recurs.
5. Preserve human/domain authority. Do not turn a correction, worker claim, or
   model inference into policy or proof by relabeling it.
6. Validate through the repository's current Makefile/release checks and assess
   total implementation, context, handoff, proof, review, repair, and future
   maintenance cost—not test success alone.
7. Keep only future-useful residue. Never retain a transcript or create a
   general improvement backlog.

Report `finding`, `evidence`, `owner`, `portability`, `action`, `proof`,
`net_cost_direction`, and `remaining_gap`. Stop for human review when the next
step changes product intent, authority, security, public contract, or materially
broadens scope.
