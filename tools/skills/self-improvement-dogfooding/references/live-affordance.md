# Observe the installed public affordances

Use this procedure when Verification reports `aw_live_affordance_dogfooding`
due or unknown. A current satisfied assessment is quiet. The requirement expires
after seven days or immediately when a declared dependency or this procedure
changes. It restricts parent-lane closeout only; continue unrelated work.

Use the existing [consumer harness](../../../../docs/maintainer/model-cli-dogfooding-harness.md).
Run one `operational-affordance` family with `--driver agent --backend sandbox
--profile standalone`, one explicit model/reasoning setting, subscription billing,
an immutable supported Codex Sandbox template and exact Linux target. Choose an
exact admitted public version or a frozen target candidate containing the current
native pair. Record that subject; do not imply that older public bytes prove a
new source change. A Linux guest on Windows supplies Linux evidence.

Create the bounded scratch directory before calling the harness. Give `--result`
a new path. Preserve the first result, including failed setup; diagnostic reruns
use separate paths and need a named cause. Stop after one representative current
provider execution plus deterministic scorer controls. Do not start a provider
matrix or retry until green. The actor receives ordinary task instructions and
installed guidance only, no source paths, expected commands or completed answers.

Authenticated local Docker Sandboxes and a supported provider are prerequisites.
No provider credential or live model job belongs in GitHub maintenance. Missing
credentials, unavailable runtime or unsupported target is **unknown**. Installation
failure, exhausted model execution or missing exercise coverage is **failed**;
record exactly what ran. Neither deterministic tests nor actor claims establish
live satisfaction.

Read the trusted run's `interactions`, independent artifact/authority checks,
subject identity, provider/model/runtime, budget, cleanup and unknown costs.
One detail read, legitimate exploration or a stale rejection followed by current
recovery is not a failure. Repeated unchanged rejection, contradictory routing
and attempted internal recovery remain findings even after correct final files.
Use the [dogfooding owner](../SKILL.md) to investigate and attribute each finding
to the smallest existing issue. The tested actor has no GitHub write authority.

Enter through ordinary native `start` and its Verification `current_evidence`
detail. Fill the exact returned assessment request, confirm its decision and
invoke its action. Supply actual observation time, result and a concise evidence
reference. Use **satisfied** only for a completed trusted exercise with the required
coverage, preserved authority and no unresolved material interaction failure.
Keep failed/unknown observations honest; routing a defect does not make it green.
Observe the resulting current status and the disappearance of the due need only
when satisfied. Handle uncertain writes through returned recovery.

Replace one concise current evidence note and the same native requirement entry.
Include source/subject digests, harness identity, first-result digest, outcome,
provider identity, scoped findings and cleanup. Keep raw transcripts and run logs
outside the repository; do not append a history or invent a scheduler. This
observation grants no independent review or general product-proof authority.
