# Ownership and authority

Resolve the owning source before changing or trusting a surface. Repository policy and instructions, domain records, generated projections and executable effects have different authority.

Read `.agentic-workspace/OWNERSHIP.toml` for declared repository ownership and the current generated `READING.json` for bounded source references. When runtime admission matters, use `agentic-workspace start --target . --task "<task>" --format json` and follow relevant current owner references.

Repository-owned content is not silently replaceable by an installed package. A managed fence owns only its exact bounded content within a repository file. Module-managed procedure and templates remain distinct from repository-owned domain records. Read current declarations rather than inferring custody from a path's name or an old installation layout.

Planning owns bounded execution records and relations; Memory owns retained knowledge; Verification owns evidence and claim interpretation. A generated reference describes its source but does not supersede it or grant effect authority.

Optional subsystem declarations in the ledger describe path scope, concerns and proof hints. They do not create a second policy engine. Use the current Verification owner for applicable evidence and claim obligations, and current Configuration custody for adoption or removal.
