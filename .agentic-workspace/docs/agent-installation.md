# Repository installation and adoption

Install the support-bearing artifact using the repository's current installation guide. Installing the executable and adopting repository guidance are separate operations.

Read the target's existing instructions first. Use the native Configuration owner through `agentic-workspace start --target <repo> --task "Adopt Agentic Workspace guidance" --format json` to obtain current adoption information and requests. Supply only the requested judgment, then execute an exact returned action with `invoke`. A task string alone does not authorize an effect.

Preserve existing repository guidance and optional domain state. Adoption creates only the owner-admitted footprint; it does not imply that Planning, Memory, or Verification has been configured. For module setup, use the workspace setup skill and the current domain owner requests.

For removal, resolve the current Configuration removal request and inspect its proposed scope. Modified or unowned files remain preserved. Do not use a historical bootstrap command as a substitute for current custody.

After adoption or removal, inspect the effect outcome and current continuation. Return to the target's configured startup instructions. Source-checkout bootstrap tools are maintenance mechanisms, not installed public commands.
