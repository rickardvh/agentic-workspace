# Repository adoption and preservation

Installing an executable does not install repository policy or domain state. Current adoption and removal belong to the native Configuration owner; the public CLI inventory is declared in `source_decision_contract.json`.

Resolve current repository adoption information with `agentic-workspace start --target <repo> --task "Adopt Agentic Workspace guidance" --format json`. Inspect the returned request and affected paths before supplying the requested judgment. Execute only the exact action returned after admission.

Preserve repository-authored guidance, modified files and optional domain state. Native custody governs which exact owned files can be removed. A familiar directory name, a legacy installation marker or an old bootstrap manifest is not current deletion authority.

Configuration adoption establishes the minimal current host footprint. Module-specific setup is a separate owner decision. Source-maintenance installers and their historical profiles are not alternate public lifecycle commands.

For packaging and payload changes, edit the owning source and refresh generated copies. Validate source/payload boundaries with the repository's maintained checks; do not mutate root Planning or Memory content merely to make it match a template.
