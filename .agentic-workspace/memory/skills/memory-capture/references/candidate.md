# Answer a returned question about a lesson

An ordinary supplied finding reaches this choice through the correction procedure.
Use its existing observation and consequence once: correct the controlling source,
retain useful advice immediately, save nothing, or preserve uncertain optional
material through `memory.candidates.requests`. Candidate reads return historical,
unconfirmed evidence, never earlier work authority or current service availability.
Use exact candidate identities for deliberate discard. `maintain` removes expired
optional rows in an authorised foreground action; passive reads do not renew age
or write. A returned `recover` request completes an interrupted local replacement
before another mutation. Unknown or conflicting files are preserved for inspection.
Local candidates do not automatically travel with a worktree or another machine;
carry needed handoff evidence explicitly or save it through its durable owner.

When selected candidates matter to current work, use their returned `consolidate`
request. Compare their existing summaries, origins, scopes and uncertainty with
the current controlling source and selected advice. Repetition or similar wording
does not establish corroboration. A useful first discovery may go directly to
publication; do not require staging or recurrence. For one-off or unsupported
material, deliberate `discard` is a successful outcome. `defer` preserves the
existing age and capacity limits without creating another record.

For a justified portable conclusion, supply `advisory_material` with the smallest
useful lesson, future cues and validity dependencies. The result returns
`publication_request` for the existing advisory publisher, carrying the selected
origins. Inspect that proposal before confirming it. To improve a declared note,
also supply `revise_source` and its exact `source_revision`; see
[advisory revision](publication.md). Keep local preferences with their local owner
and remove sensitive snippets before proposing shared advice.

Publish first. Then select a current candidate request with `operation: complete`,
the exact `candidate_ids`, and `publication: {source, revision}` from the confirmed
result. Memory checks current native publication and validity before subtraction.
After a lost publication reply, inspect or recover that result before cleanup;
after interrupted cleanup, use its returned recovery. Do not publish a duplicate.
For an actual stronger source, complete with its `receiving_source`, bounded
`receiving_consequence` and exact `candidate_evidence_requests`; current Verification
evidence must cover that source. Copied prose or a proposed correction is insufficient.

A bounded observation about useful application, contradiction or inapplicability
uses this same ordinary `material` path: reference the affected note and scope,
state what happened, and revise or discard only if that changes the next action.
Passive recall writes no feedback, renews no age and asks no usefulness question.
Missing feedback means unknown; selection counts are not a reason to retire advice.

Use this path when a check returns `future_value_candidate` with a `lesson` and
`rationale`, and the current result asks what to do with it. Read that exact
candidate and its evidence before deciding whether it would help a later task.

An explicit structured future-value observation from an admitted native check can
already place a bounded disposition question at the current frontier, without a
Memory-specific request. Judge whether the lesson belongs to a stronger existing
owner, advisory Memory, or no retention. A producer suggestion is untrusted and
is not proof of durable value. Stronger-owner disposition needs exact current
receiving source material; it does not grant that source new authority.

For advisory retention, the procedure carries the existing exact publication
proposal. Human or exact delegated authorization still applies. No-signal work
has no capture question or retrospective; no-retention is success. Carriage keeps
explicit candidate evidence and pending claim consequences across reentry. Do not
silently drop those references during a partial handoff.

Prose/routing maintenance and governing decisions retain their own owners. Do not
manufacture a write request, edit stale source bytes, or treat capability approval
as permission to retain a particular lesson.
