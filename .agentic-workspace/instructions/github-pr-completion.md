# Repository implementation PR completion

Every implementation PR must fully resolve at least one existing issue and include
its closing reference. Shape each implementation leaf so one coherent PR can
satisfy its intended outcome and acceptance criteria. Complete the required
implementation, behavioural evidence and source reconciliation before presenting
the PR as ready for independent review. An unchecked completion audit or known
acceptance gap means implementation work remains; keep working instead of
submitting the partial result as complete.

Do not narrow an issue, create a token issue, move required acceptance work into
a follow-up, or close an issue merely to make a partial PR appear complete.
Stacked PRs must each close an honestly bounded issue. Broader parent issues may
remain open for their separately defined outcomes. Preserve the independent
review boundary: implementation completion does not supply review or approval.
