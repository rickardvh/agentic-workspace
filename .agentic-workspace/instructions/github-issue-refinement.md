# GitHub issue refinement

Use the repo-owned issue-shaping procedure before changing an existing issue's
intent, scope, acceptance criteria or closure boundary. Resolve the registered
procedure and read the current issue and relevant comments before mutation;
if the procedure is unavailable, preserve the issue and expose that missing
procedure. Keep current template headings unless the human requests a reshape.

The selected route supplies applicability only. It grants no external-write
authority or issue closure. Use the creation route only when a distinct new
issue is actually needed.
