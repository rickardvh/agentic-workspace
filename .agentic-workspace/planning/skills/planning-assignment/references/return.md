# Admit and integrate returned material

Use after a delegated result returns, fails, blocks, stops or becomes stale.
Read current Assignment/delegation state and exact returned material. Worker claims
are untrusted; the native owner checks identity, scope, baseline, source and transport.
Supply only the requested semantic return judgment, never infer admission from a
successful process or matching packet seal.
Follow `assignment_context.next_step` for return judgment and the admitted patch's
current integration proposal. Preserve the effect's current continuation/reentry;
the executed-result custody is required. Answer the exact reference with semantic
fields, or an empty answer when selecting the supplied proposal. Do not replace
carried requests with an isolated judgment envelope from a detail bundle. Invoke
the resulting exact integration action, then perform the initiating host's proof.

```agentic-owner-reference
{"kind":"request","owner":"assignment","id":"assignment/judge-return/v1"}
```

Malformed, stale, duplicate, blocked or widened returns use the current exact
reject/repair/reassign/supersession/recovery path when available. Missing operations
remain explicit gaps; old `assignment.*` recipes are not fallback authority.
Integrate only an admitted result through its exact owner action. Consume an
offered Planning adoption/continuity action only when that owner has established
its postimage. It does not settle plan relation, semantic intent or selector custody.

Then use workspace proof-selection and Planning intent/closeout sources. Worker
claims never authorize those conclusions. Workers cannot widen scope or close parent
work; explorers cannot write or claim implementation; reviewers cannot implement
without new authorization. Keep current bounded returns compact; expand for named
conflict, risk, uncertainty, scope change or human override.
