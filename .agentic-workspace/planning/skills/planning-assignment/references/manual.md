# Carry a complete manual assignment

Use the current owner's exported sealed Assignment only when manual transport is
admitted. Its `manual_presentation.prompt` is ready for a recipient without AW or
repository access. The same presentation is available through host worker action
`manual`. In compact entry, read the exact `/task_requirements` detail reference
with the same work context to obtain the presentation and continuation. It contains
every required captured input inline within existing bounds;
references identify provenance and do not replace content. Confirm the destination
may receive the captured sources when answering context completeness. Missing
meaning or a disclosure/size limit requires preparation, never silent omission.

Give the recipient the prompt and request only new answer/findings, requested
artefacts, unresolved questions and stop conditions. Keep the sealed packet and
identity with the initiating host. The recipient need not operate AW, expand lazy
inputs or reproduce hashes and request arrays. The host uses worker action `return`
to wrap only actually supplied material; ask for missing or ambiguous fields rather
than inventing them.

Export is preparation, with no observed delivery or execution. Use the current
delegation retention request/action before a pause when no adequate continuation
exists. Planning work uses its own existing handoff retention; direct work can use
the owner-local manual continuation. Fresh `start` returns the exact task's retained
packet/reentry under `task_requirements.delegation.manual_continuation`. Follow that
through current owners; a retained packet alone grants no current permission.

Submit the wrapped return and answer the current manual report request with the
reported producer kind and delivery/execution provenance. Unknown stays unknown.
A pasted answer does not authenticate a person, model, product mode or independent
lineage. A model cannot substitute for the explicitly configured human owner;
simple human Verification decisions keep their smaller current decision route.

After the report is committed, follow the returned exact reentry and Assignment
judgment. Read-only analysis remains unproven; partial findings with stop conditions
cannot discharge the pending assignment. Use repair/reject for unsuitable material.
Retain the current settlement action after judgment when needed for continuation.
Planning adoption, Verification proof, independent approval and completion remain
separate. Changed work or source requires its current owner route; never re-execute
external work merely because a reply was lost. Exact committed local carriage can
be recovered without asking the recipient to work again.

If a changed assignment encounters retained pending or partial manual carriage,
follow its exact prior-disposition request before retaining the replacement.
Disposition preserves historical material and unknown delivery/execution; it does
not admit an old answer for changed work or authorise repeating external work.

Temporary delivery files use their existing resource lifetime; clean them through
that owner only after pending carriage and needed evidence are safely retained or
dispositioned. The manual continuation stores one reference for this task, not a
queue or permanent transcript archive. Host framing, token use and external product
execution remain unknown unless actually observed.

The workspace-owned, local-only `.agentic-workspace/local/delegation-manual/`
pointer preserves pending carriage and exact interrupted recovery. Terminal
settlement or prior disposition offers `delegation.retirement`; it does not make
the evidence disposable. Preserve material through any owner that still needs it.
Use the exact retirement request only when no pending work or needed evidence
remains, setting both disposition flags false and recording the reason. Current
Planning, Memory or Verification references block retirement. Partial or uncertain
carriage remains protected.

The resulting owner action removes only the authenticated lifecycle's exact
packet-bearing effect and run files. It leaves a small retirement receipt and
pointer; a later lifecycle retires the preceding receipt too. Unknown files are
preserved. If entry reports `retiring`, follow its exact recovery invocation;
never scan or delete this namespace yourself. Package adoption and removal preserve
this local state for its current owner.

Retired pointers remain internal replay/recovery barriers. Ordinary entry omits
their continuation and retirement fields; an exact manual request can still
recover its receipt, and pending or interrupted carriage stays visible.
