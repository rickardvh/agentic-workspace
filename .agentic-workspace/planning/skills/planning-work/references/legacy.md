## When explicit selection observes a legacy aggregate

Use this path only when Planning reports aggregate migration input. `state.toml`
can supply historical owner relations, never current status, revision or custody.
Read the canonical owner and use the returned selection request, then invoke
`planning.reconcile`. With several candidates or unfamiliar accompanying material,
choose one exact `legacy_aggregate.selection_requests` entry. An unresolved relation
still blocks its dependent worktree creation. Without a safe selection, preserve
the named gap; use ordinary creation or explicit canonical-owner discovery for
other current work. Do not invent a selection or retirement request.

Preserve useful aggregate-only intent through the canonical owner's update.
Unfamiliar material stays preserved until its relations can be represented safely.
After current selection custody commits, use the exact terminal retention request
for `state.toml` only when no unresolved intent or continuing value remains there.
The owner guards source and consumers and supplies interruption recovery. After
retirement, reads use the same canonical owner; fresh setup creates no aggregate.
