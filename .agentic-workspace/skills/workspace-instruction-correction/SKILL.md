# Apply a correction or useful finding

When the user asks what worthwhile improvements the repository's retained
knowledge supports, begin with the [selected review](references/review.md).
The user need not supply a finding or know the components that hold it.

During ordinary work, use [related findings](references/related.md) when
already-relevant retained facts together could change the next action or claim.
After a verified correction, use that same path to reconsider affected advice;
finishing the original edit alone does not settle its continuing usefulness.

Use this method when a user correction, source conflict, test finding or useful
improvement could change current work or prevent future rediscovery. Apply trusted
corrections to the task first. Compare the actual sources under the
[evidence rules](../workspace-startup/references/evidence.md), then choose the
source that should change: code for a defect, an instruction for a rule, a skill
for a reusable method, or Memory for advice. The component responsible for that
source is its owner. One-off information or an already-correct source may need no
saved change. Evidence of a problem does not itself authorise publication.

Use [the selection question](procedure.md), or follow the same source directly:

- [Decide which source should change](references/destination.md).
- [Publish a repository or machine-local instruction](references/instructions.md).
- [Save advice, a decision, or a method repair](references/other.md).
- [Check whether policy permits a proposed improvement](references/opportunity.md).

For a managed source change, use the configured invocation and
[exact returned owner request/action](../workspace-startup/references/owners.md).
For ordinary repository files, use the authorised editing workflow. Verify the
receiving source and relevant effect before saying the correction is saved.
If a required managed operation is unavailable, name that gap and preserve its state;
independently authorised work may continue.
