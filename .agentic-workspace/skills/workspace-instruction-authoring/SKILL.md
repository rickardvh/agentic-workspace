# Author a repository rule

Use this method when asked to create or revise a persistent repository instruction,
or when a correction has already selected an instruction as its destination.
Reuse that choice and the user's existing authority; do not fabricate a finding or
repeat destination selection. A one-off request needs no saved rule. A reusable
method belongs in a skill, a supported setting in configuration, and advice with
changing assumptions in Memory.

Inspect the intended behaviour and existing instructions first. Revise an adequate
source in place, preserving unrelated content and binding requirements. Choose
where the rule applies separately from whether it travels with the repository or
stays on this machine. Plain Markdown is suitable only for deliberately global
guidance; use path scope for work limited to particular files. Ask only for a
missing choice that materially changes the requested rule.

Read [the Markdown format](references/format.md) when shaping scoped guidance or
named consequences. Apply the installed [writing guide](references/writing.md)
and any applicable host writing rules. Do not copy governing policy into the rule.
Then follow [publication and inspection](references/publish.md), or select
[the current authoring need](procedure.md) for either reference.

Stop when the exact source is published or revised and a fresh observation
establishes its intended applicable effect or names the remaining gap. Saved bytes
alone prove neither consumer consistency nor that an agent followed the rule.
