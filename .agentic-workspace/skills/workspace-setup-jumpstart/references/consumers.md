# Complete setup needed by the current task

Use the repository sources this task already needs to identify a concrete missing
connection. A documented checking rule without a usable selected check, a lesson
whose future use would prevent rediscovery, or work that cannot safely survive an
interruption can justify setup. An absent manifest or empty note directory alone
does not. Do not survey every module, scan the repository or run setup on each task.

Keep the original task and its permissions. Resolve current enablement and local
limits through the startup method when those facts are missing. Explicit module
exclusions, disabled AW and unchanged deferrals remain authoritative. Infer routine
choices from current repository instructions and supported scripts. Ask only for
a missing user-owned decision, credential, external access or explicit human
judgment; name the affected outcome. Continue independent work while a gap remains.

## Connect the evidenced need

Use only the relevant branch below, reusing adequate existing state.

- **Checking rules:** follow [proof selection](../../workspace-proof-selection/SKILL.md)
  and compare its current strategy with the source-owned checking expectations.
  If a reusable expectation has no route, author the smallest declaration in the
  repository-owned `.agentic-workspace/verification/manifest.toml` through the
  authorised repository editing workflow. Preserve existing declarations and
  reference the actual rule/script; derive path scope, command, prerequisites and
  claim limits from it. Do not invent a test or copy a whole maintainer manifest.
  A minimal declaration uses `schema_version = "agentic-workspace/verification-manifest/v1"`,
  a `[protocols.<name>]` section with relevant `applies_to_paths`, and a
  `[proof_routes.<name>]` section with `protocol_refs = ["<name>"]` and the actual
  `commands`. Protocol `steps` and `authority_refs` can retain the source rule
  and what the check establishes. Use the repository's
  actual execution environment; configuring a route does not establish readiness.
  Re-enter the same work through `start`, select the returned strategy/check,
  execute its exact admitted action and interpret the actual receipt. If native
  execution cannot support the required environment, keep the scoped gap explicit;
  a host check may supply operational evidence without becoming an admitted receipt.
- **A future-useful lesson:** use the current Memory advisory publication request
  under [Memory capture](../../../memory/skills/memory-capture/SKILL.md).
  Supply the bounded lesson, source and rationale, deliberate future path/activity
  cues, and the dependencies whose changes would require reconsideration. Use the
  owner to construct and publish the note and manifest. Canonical rules stay in
  instructions or code; one-off findings and already adequate advice need no note.
  Resolve fresh relevant work to check delivery and an unrelated scope to check
  exclusion. Publication alone does not prove selective recall or factual truth.
- **Continuity:** use [Planning work](../../../planning/skills/planning-work/SKILL.md)
  when agreed intent, dependencies or unfinished follow-through would otherwise
  be lost. Reuse adequate issue/owner records and explicitly relate the current
  task before resuming one. Do not create a plan merely to mark setup complete.

If the responsible component has no supported operation, identify that operation
and the dependent work. Configuration cannot author module-owned operational state
or certify a consumer by recording `owner-managed`.

## Observe the result and resume

Verify the behaviour that motivated setup: a selected check really ran and its
claim stays within the evidence; useful advice appears only for its declared
future use; or a new session can continue the actual unfinished work. A current
payload, saved setting, enabled module or setup assessment proves none of these.

Use returned continuation after each authorised effect. If a result is lost,
inspect current state or follow exact recovery before acting again. Preserve a
committed effect when only its next response failed; never replay it to recover
context. Changed governing sources require fresh selection of only their affected
consumers. Reuse unchanged working state without new records, questions or checks.

Resume the user's original task. Before claiming it complete, distinguish its
actual outcome, observed setup behaviour and any remaining dependent gap. Stop
when the applicable consumer works; unrelated absent state remains absent.
