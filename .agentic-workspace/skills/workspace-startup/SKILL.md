# Agentic Workspace

Read applicable repository/local policy. Keep clear work direct. Skills provide
procedure; agents judge meaning; domain owners retain facts, evidence, effects
and currentness. Skill selection grants no authority.

At runtime-capable session entry, and after a dependency action may have changed
the resolved AW artefact, obtain one current ordinary `start` observation unless
this session already has a sufficient observation of that resolved artefact and
setup basis. Follow a pending Configuration assessment to its installed material
and existing setup procedure, even for an unrelated task. Do not require update
wording, a payload target or a new checked-in skill. The runtime returns current
setup text when local procedure is old or absent. Reuse settled observations;
this is a cheap lifecycle check, not a full setup review on every task. Without a
runtime observation, package integration remains unknown.

Use [the procedure question](procedure.md) to select only needed detail, or follow
a known reference directly:

- [Ordinary work and responsibility boundaries](references/ordinary.md).
- [Evidence acquisition and sufficiency](references/evidence.md).
- [Exact current owner requests and effects](references/owners.md).
- [Correction, reconciliation and residue](references/reconcile.md).
- [Unavailable runtime](references/unavailable.md): source reads remain possible;
  current runtime facts remain **unknown**. Do not mutate managed owner state.
- [Interpreting a current restriction](references/constraints.md).

Use the configured invocation for current facts/effects. With native routing,
select `workspace/startup` and carry the returned procedure request; answer only
with the current semantic judgment. Without it, use these same Markdown sources.
The unavailable path uses `.agentic-workspace/READING.json` and its ownership
ledger binding; read that reference before making tree-only state claims.

Do not load every branch or require AW calls for sufficient direct work. Missing
or replaced skills never waive repository policy or domain-owner restrictions.
