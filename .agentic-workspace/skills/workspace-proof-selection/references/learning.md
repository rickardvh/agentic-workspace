# Decide whether a returned lesson should be saved

Use this reference when the current result supplies a `future_value_candidate`
or an unresolved request about retaining one. Read the candidate's `lesson` and
`rationale`, then decide whether a later task would benefit and which source
should hold it. A failure or retry alone does not require a new note.

Current selected owner detail delivers current selected Memory advice with its ordinary
answer, expanding selected large detail for the active judgment. Treat it as
advisory, never as proof or permission. A currently admitted command may explicitly
emit a bounded `future_value_candidate` with `lesson` and `rationale`. The owner
then asks for the remaining materiality/strongest-owner disposition; failures and
retries alone do not nominate learning. Carry that exact pending request through
partial work or handoff, and use the existing capture authorization if advisory
retention is selected. No-retention is a valid disposition.

For `stronger-owner` or `already-absorbed`, name the exact current
`receiving_source` and supply `receiving_consequence`: a bounded `claim`, an
`evidence_reference` and its `proof_subject` from current Verification. The
admitted check must include the receiving source among its source inputs.
Judge whether that check establishes the claimed effective consequence; copied
lesson text, a filename or command success alone does not establish absorption.
Keep stable configuration/method separate from transient service availability,
which must be reobserved. This disposition grants no learned-skill promotion,
independent review, policy or completion authority.
