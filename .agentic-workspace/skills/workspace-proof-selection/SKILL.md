# Select and interpret proof

Before choosing validation or authoring tests, apply
[the testing judgment](references/select.md) to the actual outcome and failure
risks. It is the portable default even without Verification or a host strategy;
explicit applicable repository, user and host requirements take precedence.
Reuse adequate current observations. Obtain missing source-bound Verification
facts through `start` when they can change the decision; a check or completion
claim does not itself require a native acknowledgement. Verification records its
own executions and judgments. Other evidence retains its actual provenance and
coverage. A passing command alone does not establish the whole outcome.

Use [the question](procedure.md) or the same sources directly:

- [Choose evidence, permanent coverage and execution cadence](references/select.md).
- [Run the check selected by Verification](references/execute.md).
- [Use the current proof continuation](references/receipt.md).
- [Decide what the results support](references/claim.md).
- [Recover when execution happened but continuation failed](references/recovery.md).
- [Handle a returned lesson worth retaining](references/learning.md).

Follow [exact owner carriage](../workspace-startup/references/owners.md).
Stop when the required evidence supports the requested claim, or report the exact
missing result. Selecting this procedure does not grant proof or review authority.
