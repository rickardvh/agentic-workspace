## Missing tooling or another owner's boundary

Use the configured invocation and artifact-verified installed distribution. An
unavailable runtime supplies no configuration or Assignment permission. Follow
the [read-only startup fallback](../../workspace-startup/references/unavailable.md)
and preserve the exact affected gap. Only a development source checkout needs
[source preparation](source-checkout.md).

Preserve unrelated keys, comments, files and domain state. Assignment owns task
admission, module owners own their state, and Verification owns proof and claims.
Do not broaden Configuration's supported writer to fill another owner's gap.
Use its current route when the requested behavior depends on that owner; unrelated
authorized work can continue.
