# Maintain one canonical repository method

When changing a skill, inspect the source that the intended consumer actually
selected. Repository-owned bundles may be edited under current task authority.
Package-managed installed bundles must be changed at their package source and
refreshed through Configuration; do not patch installed bytes as customisation.
Adapt a package method in a distinct repository-owned bundle when the task calls
for a local method, and state its narrower applicability.

For an edit or merge, preserve the accepted method's useful decisions and move
links to the surviving source. For replacement, remove the old repository-owned
registry entry and stale references/exposure after the replacement works. For
removal, remove its owned files and declarations, preserving unrelated resources.
Do not leave two methods competing for the same canonical job.

AW route collisions return multiple `sources`; they do not select by registry
order. Select the intended `source_ref` and `skill_id` explicitly. If both methods
are useful, give them distinct descriptions and route identities. Reobserve after
renaming or replacement; old source-bound answers cannot approve the new method.

For requested host exposure or adoption, use
[setup](../../workspace-setup-jumpstart/SKILL.md) and the current Configuration
request with `job: expose-skill` (or `remove-adoption` for its supported removal).
Configuration maintains package-owned exposure and checks collisions. Preserve
repository-owned bundles; its installed entry exposure is not a universal custom
skill publisher. For a custom bundle use the selected host's supported discovery
path when available, or read the exact `SKILL.md` directly. Name an unsupported
host exposure rather than editing package-managed adapters or promising universal
host discovery.

Verify from the intended consumer: the surviving file and selected resources are
available, declared dependencies identify current files, and the removed method
is no longer discovered through its former entry. An unrelated startup should
not load the new body. Stop after that result; skill publication does not prove
the repository task complete or replace its required independent review.
