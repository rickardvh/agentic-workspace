# Bound the outcome and its dependencies

Compare original intent, local interpretation, parent/larger intent, non-goals,
negative invariants and escalation triggers before choosing slice boundaries.
A lane/epic classification is agent judgment, not a native phase or a task-word
match. Split genuinely independent lanes; do not hide unrelated work in one plan.

When a slice is ready for bounded execution, its optional `assignment_inputs`
records result class, input references, mutation paths, proof classes and accepted
dependency references with exact revisions. Use the existing creation/update
request to retain it alongside intent and constraints. Dependencies declared by
reference must have accepted source revisions; changed or missing acceptance and
blocked frontiers require refinement. This definition enables Assignment to carry
the shaped work without another semantic reconstruction. It is not a scheduler,
proof result or new mandatory plan for ordinary direct work.

Use current Planning detail and its exact creation/update request to establish the
smallest bounded decomposition. Preserve parent and issue relationships, acceptance
evidence, invariants, dependencies and the continuation owner. Select only the next
ready bounded slice through its owner. Prep-only authorization does not permit
product source, dependency, database or application scaffold changes.

Passing a narrow check cannot redefine the parent outcome. Use the shared
[intent comparison](../../planning-closeout-trust/references/intent.md) before
treating the decomposition as sufficient. Native restrictions remain current.
