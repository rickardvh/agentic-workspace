# Delegation posture

Repository and local configuration own Assignment policy, target restrictions, transport authority and independent safety. Skills provide procedure; the agent supplies task applicability and comparative judgment. Model confidence and price labels do not grant execution capability.

Resolve current requirements through `agentic-workspace start --target . --task "<task>" --format json`. Follow the returned Assignment requests to state required result/proof classes, judge applicable target restrictions, and compare feasible execution configurations. Use only exact returned requests and actions; do not manufacture dispatch or override authority.

Choose on total successful-completion cost, including context acquisition, handoff, validation, retries, repair and integration. Keep uncertainty explicit where outcomes have not been measured. A configured transport is not proof of host capability or result constructibility.

When a nonlocal target is selected, use the current sealed handoff and its admitted execution route. The native `worker` command projects captured input and assembles unproven return re-entry; it does not admit results or prove completion. Reconcile return evidence through Assignment and Verification before integration or claims.

An unavailable alternative cannot silently authorize local implementation. Preserve current source restrictions and use the owner's recovery route. A skill does not create permission to delegate, launch workers, review one's own implementation or widen the user's task.

Keep durable policy in its source, task-specific reasoning in current work, and outcome evidence with its existing owner. Do not create an additional scheduler or command catalogue.
