# Configuration reference

The canonical ordinary procedure is `../skills/workspace-startup/SKILL.md`.
For a configuration outcome, load `../skills/workspace-setup-jumpstart/SKILL.md`.
This reference introduces no second setup loop or current-state authority.

Repository and local configuration hold durable human choices and necessary
environment declarations. Current questions, source revisions and exact writes
come from the Configuration owner through the configured native `start`/`invoke`
tools. Preserve unrelated source bytes and stronger shared policy. An unavailable
choice remains an owner gap; neither a filename nor a successful query grants
adoption, source-transfer, proof or completion authority.

Package payload refresh is an explicit Configuration concern. Discover current
payload choices through the owner-returned `payload_discovery_request`, inspect
an exact file proposal, then submit its authorized answer and invoke its returned
action. Refresh only the artifact-declared files. Repository policy, domain state
and machine-local state are outside that package file set. Re-resolve after each
write; use an offered recovery request after an interrupted publication.

A second pass should report current bytes without writes. Payload identity alone
never establishes that the user's broader configuration or adoption intent is
complete. Required semantic source dispositions remain with their real owners.
